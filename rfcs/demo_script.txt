0:00-2:00 — PERSON A: INTRODUCE THE PROJECT

“AI Studio is a platform for building agents around business workflows. We’re demonstrating it through Payroll, where understanding a paycheck change can involve detecting an issue, investigating it, documenting the findings, and answering follow-up questions.

Instead of building each agent separately, we use a template-driven approach through an agent factory. A template defines the agent’s starting behavior and configuration. We then choose its model, give it access to the APIs it needs, and explicitly configure which other agents can provide context.

This gives us two ways to supply information: an agent can read authorized source data, or it can consume context produced by another agent. Those permissions let us connect agents into a workflow while controlling what each one can access.

Once created, we make the agents available within the Payroll service, so users can work with them alongside the payroll records.

Our demonstration follows three connected capabilities.

First, Anomaly Detection uses Jev to check paycheck data across the payrun. When a user chooses Review, the agent runs an LLM investigation to produce a brief explanation grounded in the available evidence.

Next, the Incident Report agent uses context from Anomaly Detection to create and store a report.

Finally, the Chat agent can use permitted context from both agents to answer follow-up questions.

As you watch the demo, look for the common foundation: templates create the agents, permissions connect them to information, and shared context connects their work.”

4:00-5:00 — PERSON A: TIE THE DEMO BACK TO THE PPT

“What we just saw brings the platform story together.

The template-driven agent factory made agent creation repeatable. We configured each agent’s purpose, model, and access using the same foundation.

The access controls connected agents to the information they needed—both business APIs and context from other agents.

Inside Payroll, those pieces became a connected workflow: Jev detected paycheck anomalies, an explicit Review action triggered the LLM investigation, and the Incident Report agent turned that investigation context into a stored report. Chat then provided a way to ask follow-up questions using context from both agents.

This connects back to the presentation’s three themes: create agents faster, control their access to data, and choose where inference runs.

Payroll is our reference implementation. Extending to another domain requires its own integrations and policies, while reusing the agent factory, templates, permissions, and context-sharing foundation.”
